# 원본 데모의 충돌 처리

원본 `KartRider.exe`와 원본 `.rho` 에셋만 보고 확인한 내용이다. 이 저장소의
C 구현이나 KTRK 익스포터는 근거로 쓰지 않았다. 추측한 부분은 마지막 절에
따로 모았다.

## 대상

- `input/KartRider.exe`, SHA-256 `812FB0FF…B58C`
  (`C:\Program Files (x86)\Nexon\KartRider Demo\KartRider.exe`와 동일)
- `Data/track_*.rho` 안의 `track.1s`
- Ghidra 프로젝트 `analysis/ghidra-project`, 스크립트 `DeveloperTools/AssetPipeline/ghidra`

주소는 전부 VA다. 이미지 베이스가 `0x400000`이고 모든 섹션에서
`raw offset == RVA`라, 파일 오프셋은 `VA - 0x400000`으로 바로 나온다.

산출물:

| 파일 | 내용 |
|---|---|
| `analysis/reports/body-collision-decompilations.c` | 바디 충돌·그리드 빌드 |

## 엔진에 "충돌" 클래스는 없다

이 엔진은 컴파일러 RTTI를 거의 쓰지 않는다. 바이너리 전체에 `.?AV` 타입
디스크립터가 `type_info` 하나뿐이다. 대신 `FUN_00479240(이름, 타입서술자,
CreateObject, 0)` 형태로 클래스를 직접 등록하며, 이 표에 **197개 클래스**가
들어 있다 (`the::` 네임스페이스).

그 197개 중 3D 충돌을 뜻하는 클래스는 **하나도 없다**. `Collision`, `BSP`,
`Octree`, `Wall`, `Floor`, `Terrain` 같은 이름이 전혀 없다. `the::IntersectRect`,
`the::IntersectAlphaRect`, `the::IntersectVolume`이 있긴 하지만 `the::Panel`,
`the::Window` 계열과 같이 등록되는 UI 히트테스트용이다.

충돌은 클래스 계층이 아니라 **`TrackService`가 들고 있는 삼각형 그리드 하나**로
처리된다.

트랙 씬 그래프의 노드 타입은 9종이다.

| 클래스 | 이름 문자열 VA |
|---|---|
| `the::TrackObject` | `0x5764d8` |
| `the::ToDummy` | `0x576504` |
| `the::ToBlackPlane` | `0x57652c` |
| `the::ToMesh` | `0x57655c` |
| `the::ToEventMesh` | `0x576584` |
| `the::ToRoad` | `0x5765b0` |
| `the::ToMinimap` | `0x5765d8` |

| `the::TrackContainer` | `0x576630` |

## 충돌 자료구조: 4단위 셀의 2D 해시 그리드

트랙 로드 시 `FUN_00432390`이 씬 그래프를 재귀로 걸으며 삼각형을 하나씩
**월드 공간으로 구운 레코드**로 만들고, `FUN_004bb730`이 그것을 XY 격자에
래스터라이즈해 각 셀 버킷에 넣는다. Z는 격자에 쓰지 않는다.

- 셀 크기 `DAT_005724e0` = **4.0** 월드 단위. 빌드(`FUN_004bb730`)와 두 질의
  (`FUN_004bc200`, `FUN_004bc530`)가 같은 상수를 쓴다.
- 셀은 `(x, y)`를 해시한 키로 맵에 들어간다. 밀집 배열이 아니다.
- 질의 쪽 셀 인덱스 유효 범위는 `0 … 0x7d0`(2000).
- 빌드 쪽 가드: 삼각형 세 정점의 **x와 y가 모두 `[0, 2000)`** 이어야 등록된다
  (`DAT_005712bc` = 2000.0). z는 검사하지 않는다. 즉 충돌 세계는 원점 기준
  양의 사분면 2000×2000이다.

### 삼각형 레코드 (0x40바이트)

`FUN_00432390`이 `FUN_00478523(0x40)`으로 할당해 채운다.

| 오프셋 | 내용 |
|---|---|
| `+0x04` | 정점 0 (월드 변환 완료) |
| `+0x10` | 정점 1 |
| `+0x1c` | 정점 2 |
| `+0x28` | **면 법선**, 정규화됨 |
| `+0x34` | 세 정점 z의 최소 |
| `+0x38` | 세 정점 z의 최대 |
| `+0x3c` | 표면 재질 레코드 포인터 |

법선은 **빌드 시 계산된다**: `normalize(cross(v1 - v0, v2 - v0))`
(`FUN_00428490` 외적, `FUN_00428500` 정규화). 에셋에서 읽어오는 값이 아니다.

`+0x34`/`+0x38`의 z 범위는 브로드페이즈 전용이다. `FUN_004bc200`이 셀을 훑을
때 질의 선분의 z 구간과 겹치지 않는 삼각형을 삼각형 테스트 전에 버린다.

## 충돌 가능 여부는 에셋이 정한다 — `property/road`

`FUN_00432390`의 첫 동작이 노드에서 `L"road"`를 찾는 것이다.

```
0x432390  노드의 property 블록을 연다
          없으면 → 부모에게서 받은 레코드를 그대로 물려받는다
          있으면 → 그 안에서 "road"를 찾는다
              없으면 → param_2 = 0
              있으면 → 0x18바이트 표면 레코드를 새로 만들어 덮어쓴다
          if (param_2 != 0) { 이 노드의 삼각형을 전부 그리드에 넣는다 }
          자식마다 FUN_00432390(this, child, param_2) 재귀
```

**`road` 속성이 걸린 서브트리만 충돌한다.** 나머지 노드의 삼각형은 그리드에
아예 들어가지 않으므로 어떤 질의로도 맞출 수 없다. 그리고 표면 레코드가
`param_2`로 자식에게 전달되므로 **부모에 걸면 자식이 상속**한다.

이 구조는 에셋에서 그대로 확인된다. `track.1s`는 UTF-16으로 이름을 저장하고,
`property` → `road` → `surface` 중첩이 바이트로 보인다.

```
"property" 00000000 00000000 01000000
   04000000 "road" 00000000 01000000
      07000000 "surface" 02000000 …
```

트랙별 개수 — `road` 속성 노드 수는 익스포트된 메쉬 수보다 훨씬 적다.

| 트랙 | `road` 속성 | 익스포트 메쉬 | 삼각형 |
|---|---|---|---|
| desert_I01 | 30 | 157 | 13188 |
| desert_I02 | 41 | 176 | 11914 |
| desert_R01 | 54 | 388 | 19292 |
| forest_I01 | 30 | 518 | 12468 |
| forest_I02 | 34 | 692 | 23184 |
| forest_R02 | 19 | 1041 | 23275 |
| ice_I01 | 34 | 487 | 21840 |
| ice_I02 | 27 | 268 | 11853 |
| ice_R01 | 61 | 460 | 50046 |
| village_I01 | 45 | 348 | 12575 |
| village_I02 | 27 | 419 | 14303 |
| village_R01 | 32 | 375 | 17697 |
| village_R03 | 41 | 620 | 21531 |

메쉬 수는 이 저장소의 KTRK 익스포트에서 센 것이고 노드 세는 기준이 달라
1:1로 비교할 수는 없지만, 자릿수가 다르다는 사실은 분명하다. **트랙 지오메트리
대부분은 충돌하지 않는 순수 장식이다.**

### 표면 재질

`road` 블록 안에서 문자열 세 개를 읽는다.

| 속성 | 저장 위치 |
|---|---|
| `surface` | 레코드 `+0x00`, 해시 `+0x04` |
| `dust` | 레코드 `+0x08`, 해시 `+0x0c` |
| `sound` | 레코드 `+0x10`, 해시 `+0x14` |

셋 다 기본값(`DAT_005ac53c`)이 있어서 생략 가능하다. 실제로 forest_I01의
`road` 30개 중 `surface`를 명시한 것은 2개뿐이고 `dust`는 하나도 없다.

이 레코드 포인터가 삼각형 `+0x3c`에 들어가고, 질의 결과 구조체의 `[7]`로
그대로 나온다. 즉 **충돌한 면이 어떤 노면인지는 질의 결과에 실려 나온다.**

## 질의는 두 종류다 — 바퀴는 레이, 바디는 박스

여기서 바닥 충돌과 벽 충돌이 갈린다. 서로 다른 함수, 서로 다른 기하 테스트다.

### 1. 레이 — `FUN_00432fc0`

선분 대 삼각형. 표준 Möller–Trumbore다.

- 브로드페이즈 `FUN_004bc200`으로 선분이 지나는 셀만 모은다
- 행렬식 거부 구간: `det <= -1e-4`(float `0x571db8`) 또는
  `det >= 1e-4`(double `0x571db0`)일 때만 통과. 즉 `|det| < 1e-4`면 버린다
- `u >= 0`, `u <= 1`, `v >= 0`, `u + v <= 1`, `0 <= t < 1`
- 가장 가까운 교점 하나만 남긴다
- 결과: `[0..2]` 교점, `[3..5]` 면 법선, `[6]` t, `[7]` 표면 레코드

**이 질의에는 법선 필터가 붙어 있다.**

```
0x433068  MOV EDX,[EBP-0x60]        ; 삼각형 레코드
0x43306b  MOV EAX,[EDX+0x30]        ; 법선 z
0x43306f  CALL 0x00431b70           ; fabs  (fld / d9 e1 / fstp)
0x433077  FCOMP float ptr [0x00571d48]   ; 0.65
```

호출자가 넘긴 바이트 플래그가 0이면 **`fabs(법선 z) < 0.65`인 삼각형은
건너뛴다.** 벽은 이 질의에 아예 잡히지 않는다.

호출부 4곳 중 3곳이 플래그 `0`을 넘긴다.

| 호출자 | 용도 | 플래그 |
|---|---|---|
| `FUN_0042ef90` | **카트 4바퀴 서스펜션 레이** | `PUSH 0x0` |
| `FUN_004260e0` | 출발 그리드 배치 스냅 | `PUSH 0x0` |
| `FUN_004394b0` | 아래로 100단위 스냅 | `PUSH 0x0` |
| `FUN_0044d3d0` | 호출자 인자 전달 | `[EBP+0x18]` |

바퀴 레이(`FUN_0042ef90`)는 4회 루프를 돌며 바퀴마다

- 시작점 = 차체 중심 + 우측축 × `half_width` × 부호 × **0.8**
  + 전방축 × `half_length` × 부호 × **0.8** + 상방축 × `[+0x2a8]`
- 방향 = 상방축 × `[+0x2a8]` × **−2.0**

로 아래를 쏜다. 결과는 바퀴별로 `+0x244+i`(접촉 여부), `+0x248+i*12`(접촉점)에
들어간다.

### 2. 바디 — `FUN_00433310`

**OBB 대 삼각형**이다. 카트 바디는 방향이 있는 상자 하나로 다뤄진다.

호출 규약(스택 인자):

| 오프셋 | 인자 |
|---|---|
| `+0x08` | 상자 중심 |
| `+0x14` | 3×3 회전 행렬 |
| `+0x38` | 상자 반치수 |
| `+0x44` | 재수집 플래그 |

동작: 플래그가 1이면 `FUN_004bc530`으로 후보를 모으고 커서를 리셋한다. 그다음
후보를 하나씩 꺼내 **삼각형을 상자 로컬 공간으로 변환**한 뒤
`FUN_00434d40`에 넘긴다. 한 번 호출에 접촉 하나를 돌려주는 이터레이터다.

`FUN_00434d40`은 Akenine-Möller의 AABB-삼각형 분리축 테스트다. 삼각형 변 3개 ×
상자 축 3개 = 외적 축 9개를 검사하고, 이어서 상자 축 3개의 AABB 겹침을 본다.
반치수를 로컬 공간에서 쓰므로 전체적으로는 OBB 테스트가 된다.

결과 구조체는 레이 쪽과 같은 모양이되 `[0..2]`가 교점이 아니라
**삼각형 무게중심** `(v0 + v1 + v2) × 0.33333`이다.

### 카트 바디 상자의 크기

`FUN_00430830`이 매 스텝 상자를 만든다.

```
0x430830  FUN_004135a0(half_extents, [this+0x12c], [this+0x130], 0x3f333333)
```

- x = `[+0x12c]` = 카트의 `half_width`
- y = `[+0x130]` = 카트의 `half_length`
- z = `0x3f333333` = **0.7, 전 카트 공통 하드코딩**

같은 두 필드를 바퀴 레이도 0.8배해서 쓴다. 즉 **바디 충돌 상자의 높이만은
카트 에셋에서 오지 않는다.** `model.1s`의 `model_height`(0.81~0.99)와도 다른
값이다.

## 바닥/벽 판별 공식

`_DAT_00571d48` = **0.65**. 이 상수 하나가 두 군데에서 다른 방식으로 쓰인다.

**레이 질의** — 필터. `fabs(법선 z) < 0.65`면 삼각형을 건너뛴다.

**바디 질의** — 분기. `FUN_00430830`에서

```
0x4309a4  FLD float ptr [EBP-0x4c]        ; 접촉 법선 z
0x4309a7  FCOMP float ptr [0x00571d48]    ; 0.65
0x4309af  TEST AH,0x41
0x4309b2  JNZ 0x00430ac8                  ; 법선 z <= 0.65 이면 점프
```

- **법선 z ≤ 0.65 → 벽 처리**
- **법선 z > 0.65 → 바닥 처리**

즉 지면과의 각도로 따지면 약 **49.5도**(`acos(0.65)`)가 경계다. 그보다 가파른
면이 벽이다.

접촉 전 공통 조건이 하나 더 있다: `dot(속도, 법선) < 0`일 때만 반응한다.
멀어지는 중인 접촉은 무시한다.

### 두 분기의 반응이 다르다

법선 방향 성분 `vn = 법선 × dot(속도, 법선)`, 접선 성분 `vt = 속도 − vn`으로
놓으면,

**벽 분기** (법선 z ≤ 0.65)

- `[+0x2dc] = 0`, `[+0x2f8] = 1`, `[+0x2fc] = |vn|` — 충돌 상태 플래그와 세기
- 튕김 속력을 `min(|vn| × 1.5, |vt| × 0.6)`으로 **상한을 건다**
  (`_DAT_00571d3c` = 1.5, `_DAT_00571d40` = 0.6)
- 여기에 `vn × −1.5`를 더해 속도를 갱신하고, z 성분은 따로 다룬다
- 이어서 전방축·우측축과 속도의 내적 부호를 보고 어느 쪽으로 튕길지 정한 뒤
  `min(30.0, |…|)` 형태로 각속도 항을 만든다

**바닥 분기** (법선 z > 0.65)

- 속도를 `vt + vn × (−0.2)`로 교체 — 반발 계수 0.2의 정면 충돌
- `[+0x304] = |vn|`
- 각속도 두 성분(`+0x68`, `+0x6c`)을 `_DAT_00571d44` = **0.1** 비율로 깎는다

전체 디컴파일은 `analysis/reports/body-collision-decompilations.c`에 있다.

## 요약

| 질문 | 답 |
|---|---|
| 바디 충돌 방식 | OBB 대 삼각형 SAT (`FUN_00433310` → `FUN_00434d40`), 상자는 `(half_width, half_length, 0.7)` |
| 바닥과 벽이 다른가 | 다르다. 바닥은 바퀴 4개 다운레이, 벽은 바디 박스. 질의 함수도 기하 테스트도 반응식도 별개다 |
| 에셋에 바닥/벽 정보가 있나 | **없다.** 에셋은 "충돌하는가"와 "무슨 노면인가"만 말한다. 바닥/벽은 런타임에 법선으로 정한다 |
| 메쉬별 충돌 가능 정보가 있나 | **있다.** `property/road` 블록이 있는 노드만 충돌 그리드에 들어가고, 자식이 상속한다 |
| 자체 판별 공식이 있나 | **있다.** 면 법선 z를 0.65와 비교한다. 레이는 `fabs(nz) < 0.65`를 걸러내고, 바디는 `nz ≤ 0.65`를 벽으로 분기한다 |

## 확정하지 못한 것

- **`surface`/`dust`/`sound` 문자열의 실제 값 집합.** 데모 트랙에서는 거의
  전부 기본값이라 표본이 없다. 이 값을 소비하는 쪽(스키드마크·먼지·노면 소리)
  까지는 추적하지 않았다.
- **`ToRoad` 클래스와 `road` 속성의 관계.** 코드에서 확인한 충돌 게이트는
  클래스가 아니라 `property/road` 조회다. `ToRoad` 노드가 항상 그 속성을
  갖는지, 반대로 `ToMesh`도 가질 수 있는지는 `.1s` 노드 타입 태그를 완전히
  디코드해야 답할 수 있고, 하지 않았다.
- **`.1s` 컨테이너의 정확한 문법.** `property`/`road` 중첩이 있다는 것과 UTF-16
