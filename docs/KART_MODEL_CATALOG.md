# 카트 모델 카탈로그

26개 카트의 디자인·모델링·바운딩 박스를 원본 데모 에셋에서 직접 뽑은 것이다.
생성은 `python scripts/derive_kart_catalog.py`, 원본 데이터는
`analysis/reports/kart-catalog.json`에 그대로 들어 있다.

출처는 `C:\Program Files (x86)\Nexon\KartRider Demo\Data\kart.rho`
(134 엔트리)이며, 값 검증은 `docs/KART_ASSET_VERIFICATION.md`가 따로 맡는다.
아카이브는 Cotton을 `cotten`으로 적는다.

## 아카이브에 있는 것

`kart.rho`의 최상위는 카트 이름 폴더 27개 + `common/` + `kartlist.xml`이다.
26개는 아래 카탈로그의 카트이고, 나머지 하나가 `mine1`이다.

- `mine1`은 **`model.1s` 하나뿐**이다. `parameter.xml`도 텍스처도 없어서
  물리 값도 외형도 존재하지 않는다. 이름대로 아이템 지뢰 모델로 보이며,
  카트 26대에 들어가지 않는 이유도 이것이다.
- `kartlist.xml`에는 `burst3` 한 항목만 있다. 데모가 burst3로 시작하는 것과
  일치하며, 나머지 25대는 아카이브에만 있고 목록에는 없다.

## 바운딩 박스가 세 개인 이유

| 박스 | 범위 | 쓰임 |
|---|---|---|
| full | 전 서브메쉬 정점 | KTRK 헤더에 기록되는 값, 렌더 컬링용 |
| body | 서브메쉬 0(차체)만 | **물리가 쓰는 값.** `half_width`/`half_length`/`model_height`의 출처 |
| wheels | 바퀴 4개 서브메쉬 | 차체보다 옆으로 튀어나오는 폭의 정체 |

셋이 다른 값이라는 게 핵심이다. 17/26 카트는 바퀴가 차체보다 옆으로 더
나와서 full로는 물리 상수가 재현되지 않는다. 나머지 9대는 차체가 더 넓어
full 폭과 body 폭이 같다. 아래 `바퀴 초과` 열이 한쪽당 초과폭이다.

```text
half_width   = (body.max_x - body.min_x) / 2
half_length  = (body.max_y - body.min_y) / 2
model_height = body.max_z - min(0, body.min_z)
```

### 모델의 앞은 -y다

에셋 어디에도 축 이름이 없다. 서로 무관한 근거 셋이 모두 -y를 앞으로
가리킨다.

- y -0.36에 있는 9정점 8삼각형 원반은 **핸들**이고, 평균 법선이
  (0, +0.65, +0.76)이다. 위쪽과 +y를 향한다 — 운전자가 +y에 있다는 뜻이다.
- +y 쪽 바퀴가 큰 쪽이다. 카트는 뒷바퀴가 크다.
- 차체 높이가 +y 끝에서 0.69, -y 끝에서 0.50이다. 앞이 낮고 뒤가 높은
  통상적인 실루엣이다.

그래서 시뮬레이터는 모델을 z축 기준 180도 돌려 놓는다. x와 y를 같이
뒤집으므로 거울상이 아니라 회전이다 — 한쪽만 뒤집으면 좌우가 바뀐다.

### `0.png`는 내용이 없다

26/26 카트의 `0.png`가 32768픽셀 중 **2픽셀만 불투명**하고 나머지는 전부
알파 0이다. 그 2픽셀은 (255, 0)과 (0, 127), 즉 텍스처의 대각 두 모서리이며
색은 순백이다. UV 랩 모드를 잡아두려는 상투적 수법으로 보인다.
픽셀 해시가 한 종류뿐이라 26장 전부가 내용상 같은 파일이다. 아카이브의 파일
바이트 해시는 26개가 서로 다르지만 압축 결과의 차이일 뿐이다.

따라서 카트 외형을 논할 때 볼 것은 `1.png` 한 장뿐이다.

### `1.png`은 패널 아틀라스이고, 카트는 무채색이다

평평한 패널 조각을 격자로 늘어놓은 아틀라스다. 조각 사이의 빈 자리는
순마젠타 색키로 메워져 있고, 알파 0인 여백이 또 따로 있다.

불투명 텍셀에서 색키를 뺀 것이 실제 차체 면적인데, **그 면적의 대부분이
무채색**(채널 최대-최소 < 20)이다. 즉 데모 카트의 도색은 흰색·회색·검정
명암뿐이고, 카트끼리 다른 것은 색이 아니라 패널 모양이다.

## 시뮬레이터에서 보기

`build-win/kart.exe`가 위 26개 모델을 전부 내장한다. 트랙 씬과 같은 KTKZ
컨테이너로 압축해 RCDATA로 넣었고(합쳐서 130KB), 같은 로더가 읽는다.

| 키 | 하는 일 |
|---|---|
| `M` | 복구한 메쉬 ↔ 예전 8정점 상자 전환 |
| `B` | 바운딩 박스 표시 — 노랑 full, 초록 body, 자홍 wheels |
| `K` | 카트 교체. 26대 모두 각자의 메쉬로 그려진다 |

상자 쪽도 그대로 남겨 뒀다. 그게 물리가 실제로 다루는 형상이라 둘을
나란히 비교할 수 있어야 한다. 상자의 지붕 계수 `0.8`/`0.75`는 어느 원본
에셋에도 없는 값이고, 메쉬 쪽에는 그런 임의값이 없다.

도색은 원본 스킨이 아니라 데모의 상태 색(기본 빨강, 드리프트 하늘색,
부스트 주황)이다. 위에서 본 대로 스킨에 쓸 색이 없어서, 텍스처를 입히면
회색 카트가 나온다.

`tests/test_kart_model_assets.c`가 26개 모델을 전부 열어 서브메쉬 6개와
바퀴 4개를 확인하고, 차체 박스에서 `half_width`/`half_length`/
`model_height`를 다시 계산해 `src/kart_demo_data.c`의 상수와 대조한다.
그리는 형상과 시뮬레이션하는 형상이 갈라지지 않게 묶어 두는 장치다.
